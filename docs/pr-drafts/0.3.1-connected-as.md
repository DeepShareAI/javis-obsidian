## Summary

The settings tab now names the Javis account the vault is connected to:
*Connected as you@example.com. Your wiki pages sync into this vault, one way.*
The email comes from the new `email` claim in the access token. It is display
text only. Account identity and the upload account-mismatch rule still use `sub`.

- When a token has no `email` claim (the server predates the change, or the token
  was minted before it), the line stays *Connected. …* as it reads today. A live
  connection picks the email up at its next token refresh, within an hour, with
  no reconnect.
- The email is read from the keychain on every render and never written to
  `data.json`, because that file sits inside the vault.
- In the disconnected and needs-reconnect states the line never shows an email.

## What changed

- `src/shell/auth.ts`: new `JavisOAuth.accountEmail()` decodes the stored access
  token with `decodeJwtClaims`. It returns null when there is no access or
  refresh token, when the token does not decode, or when the claim is missing,
  not a string, or empty.
- `src/shell/connection-status.ts` (new): the status strings (`STATUS_TEXT`) and
  a pure `connectionStatusText(status, email)`, moved out of `settings.ts` so
  they can be unit-tested.
- `src/shell/settings.ts`: renders `connectionStatusText(...)` through
  `createEl({ text })`, which sets textContent, so an email can't inject markup.
- `tests/auth.test.ts` and `tests/connection-status.test.ts`: 9 new tests.
- `README.md`: a paragraph under "Connect it" about the account shown in settings.
- `docs/superpowers/specs/2026-09-27-javis-wiki-root-folder-design.md`: the 0.3.0
  spec's Release section no longer says "javis-server: no change", since the
  upload path guard did change (javis-server PR #162).
- Release 0.3.1: `manifest.json`, `package.json`, `package-lock.json`, `versions.json`.
